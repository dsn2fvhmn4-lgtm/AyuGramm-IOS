# Продолжение AyuGram 27.5.0 — 2026-11-01

Работа ведётся в `worktree-ayu-big-update`. iOS-сборка не запускалась. Последним сообщением пользователь разрешил собрать IPA через GitHub и скачать на ПК; попытка остановилась на недоступности github.com и api.github.com. Изменения интерфейса ещё не проверены в симуляторе. Этот документ описывает состояние исходников, а не готовый релиз.

## Внесённые исправления

- Последние исходники из передачи включены в `patches/ayugram-big-update.patch`: Lua 5.4.7, `.plugin`-бандлы, баннеры, обработка речи и остальные незаписанные изменения. Список обязательных исходников обновлён.
- `AyuVerifiedRegistry.Entry` содержит `banner`; единственное создание `Entry` передаёт его. `bannerURL` проверяет HTTPS, длину, хост, отсутствие учётных данных, пробелов и фрагмента URL.
- Баннер загружается без cookies и сохранённых учётных данных. Скачивание ограничено 4 МиБ во время приёма; редиректы также проверяются. Перед декодированием для показа создаётся уменьшенное изображение до 1440 пикселей. Кеш ограничен 24 МиБ / 32 изображениями; при смене профиля старое изображение очищается, загрузка отменяется.
- В исходники бота добавлены `/banner ID HTTPS_URL`, `/banner ID -`, кнопка в меню и отмена. Надпись верификации сохраняется при изменении баннера; баннер сохраняется при изменении надписи. Бот редактирует и подписывает `registry/verified.json`, а не `registry/index.json`. Исходники и тесты находятся в `.work/plugins-repo/tools/verify-bot`. Работающий бот не перезапускался; внешних сообщений и изменений реестра не отправлялось.
- Локальные уведомления передают идентификатор сообщения и темы для перехода, подавляют повторы в пределах последних 2048 сообщений текущего процесса, учитывают настройки превью чата и темы, скрывают имя/текст при блокировке и отключённых превью. Хук плагина не запускается для скрытого текста. Тихие сообщения показываются без звука; учитывается выключение звука для категории, чата и темы. При ошибке регистрации уведомления повтор разрешён. Повторно проверяются состояние приложения, режим-приманка и включённость уведомлений после асинхронного чтения настроек.
- Lua: ограничение 32 МиБ применяется ко всей памяти экземпляра, а не к одной аллокации. Создание строки запроса перенесено внутрь защищённого вызова: нехватка памяти возвращает ошибку вместо аварийного завершения процесса. Добавлен `ci/test_lua.py` и отдельное задание в существующий workflow Plugin API tests.
- Распознавание для запикивания речи требует поддержки обработки на устройстве и не переходит на серверное распознавание. Тайм-аут в 20 секунд завершает зависшую операцию.
- Таймер изменения громкости работает только для музыки, когда эффект включён и воспроизведение идёт. При выключении эффекта громкость восстанавливается; на паузе и при уничтожении плеера таймер останавливается. Это затухание у краёв треков, а не одновременное смешивание двух треков.
- Из Codable-модели `AyuGhostModeSettings` убрана зависимость от Postbox: методы, использующие пространства идентификаторов Telegram, перенесены в `AyuGhostMode.swift`. Исключения по типам и папкам кешируются как множества и сбрасываются по уведомлениям об изменении настроек.
- SDK Lua, Python и TypeScript синхронизированы в локальную ветку `dev-cloud-27.5` репозитория плагинов. Существовавшая правка Rust сохранена.

## Второе продолжение: оставшиеся функции в исходниках

### Архив недоступных аккаунтов

- Настройки → AyuGram → Безопасность → Аккаунты: переключатель сохранения после подтверждённого выхода по решению сервера и экран «Архив аккаунтов».
- В `LoggedOutAccountAttribute` добавлены необязательные Codable-метаданные (`peerId`, имя, время). Старый пустой маркер декодируется без включения архивирования. Метаданные хранятся в существующей записи AccountManager, отдельный `archive.json` не нужен.
- База остаётся в исходной папке. `managedCleanupAccounts` не запускает cleanup для архивов; сохранённая запись защищает папку от удаления как бесхозной. Открытую SQLite/WAL-базу не перемещаем.
- Только обработчик `account.loggedOut` в `ApplicationContext` передаёт архивные метаданные. Ручной выход и правила определения ложного логаута не менялись. Уже начатый ручной выход нельзя превратить в архив повторным callback.
- `AyuAccountArchiveStore` открывает существующий Postbox с `isReadOnly: true`, `removeDatabaseOnError: false`, без Account/Network. Read-only открытие теперь отказывается от несовместимой версии схемы до любых миграций/сбросов.
- Дополнительная проверка в `accountWithId` блокирует сетевое открытие архивов. NotificationService пропускает `.loggedOut`; Siri уже фильтрует такие записи.
- Нативный список чатов, чтение текста страницами по 100 сообщений, удаление архива с подтверждением. Экспорт JSON использует существующий `AyuChatExportWriter`, страницы по 100, предел 100 000; экспорт помечается неполным. Секретные и защищённые чаты не экспортируются; медиа-файлы не выгружаются.
- Ограничения: просмотр текстовый; экран находится в настройках авторизованного аккаунта. Если вышли из последнего аккаунта, для доступа к настройкам архива потребуется снова войти. Экран не восстанавливает авторизацию и не догружает сообщения.
- Новые исходники: `TelegramCore/Sources/AyuGram/AyuAccountArchive.swift`, `SettingsUI/Sources/AyuAccountArchivesController.swift`; проверки жизненного цикла записи подготовлены в `TelegramCore/Tests/AyuAccountArchiveTests.swift` (на Linux не запускались).

### Локальные уведомления

- Новый экран в категории «Сообщения»: группировка, аватары, «Ответить» / «Прочитать», тихие часы, уведомления об удалениях/правках, фильтр слов и фраз.
- Аватар берётся только из локального кеша через Communication Notification (`INSendMessageIntent`). Скрытые превью, секретные чаты и блокировка приложения не раскрывают аватар/текст.
- Новые категории регистрируются вместе с категориями Telegram. Действия требуют разблокировки устройства и повторно проверяют блокировку приложения. Новый учитывает глобальные/чатовые/тематические настройки и приватность, уведомляет только о допустимом сохраняемом содержимом. В открытом приложении показывает toast.

## Предупреждение при установке через сертификат — 2026-11-01

По скриншоту `photo_2026-11-01_20-43-44.jpg` найден повторяемый startup-alert: он создавался при каждом запуске standalone-хранилища. Теперь короткий «Режим совместимости» показывается до нажатия «Понятно», после чего подтверждение хранится в UserDefaults для конкретной существующей storage identity. Ключ исключён из области экспорта `ayu.`; обновление приложения, язык и переключение аккаунтов не сбрасывают подтверждение. Новый независимый контейнер требует собственного подтверждения. Текст больше не утверждает, что текущая подпись обязательно лишена App Group: уже созданное отдельное хранилище сохраняется и после смены подписи.

Алгоритм выбора контейнера, probe Keychain, UUID-маркер и базы не менялись. Это исправление повторяющегося окна, а не получение отсутствующих entitlements: расширения и встроенный кошелёк в standalone-режиме остаются недоступны. Пользователь подтвердил: приложение работает нормально, проблема только в появлении этого окна при каждом открытии. Дополнительные изменения входа или выбора хранилища не требуются.

Синтаксис `AppDelegate.swift` / `AyuStartupStorage.swift` проверен Linux swiftc; `git diff --check` чистый. Логи: `.work/codex-signing-parse.log`, `.work/codex-signing-patch-check.log`. Патч содержит 314 изменённых путей и соответствует исходникам; manifest — 239. iOS-компиляция, снимки/запись окна и проверка перезапуска на устройстве не выполнены. Проверить: первый показ, явное подтверждение, полный перезапуск, завершение до подтверждения, переподпись без удаления приложения, сохранность входа, обычная установка с App Group.
