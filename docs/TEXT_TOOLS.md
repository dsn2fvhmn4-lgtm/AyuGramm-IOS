# Message text tools — development source after build 8

Long press a cloud message in its current chat:

- **AyuGram · Repeat Text:** review a confirmation, then append the message text/caption to the end of the current draft, separated by a newline when the draft is nonempty. Formatting uses the native input-entity converter; malformed entity ranges are discarded. Existing draft blocks are preserved through the native structural replacement method and input undo flow. Nothing is sent automatically. Attachments, original reply targets and forwarding attribution are not copied; current reply/send-as/send options remain the native composer's state. This is a partial iOS adaptation of Desktop Repeat Message, not its immediate media resend flow.
- **AyuGram · Find Phrase:** normalize whitespace and open native in-chat search with the resulting query. It is normal Telegram search, not a regex or guaranteed exact-match search. Current thread/search behavior follows the native search implementation. Queries over 128 characters are rejected rather than silently shortened.
- **AyuGram · Copy Message IDs:** copy the chat ID and message ID with a native copy toast. Chat IDs use the same user/group/channel formatting as profile IDs. This action copies metadata, not message text, and is available independently of text export eligibility.

Visibility switches: **Settings → AyuGram → Message Menu**. The three new switches default on, migrate independently and persist per account. Changing them affects newly opened menus.

Repeat/Search are limited to ordinary locally available messages from the actual chat. They reuse the local engine protection/expiry checks and re-read the message before preparing text. Secret, protected, expiring, sponsored and service content is excluded. Repeat additionally requires native permission to send, no active message edit, nonblank text, at most 4096 UTF-16 units and 8192 UTF-8 bytes. Current chat protection/send/edit state is checked again when the confirmation is accepted and after the native recording-discard prompt. The prepared text is a snapshot; an already open confirmation/draft is not continuously synchronized with subsequent message edits/deletions. Message IDs remain metadata even when content is protected. No media fetch is started by these tools.

Native flows handle recording discard, draft undo, Premium emoji restrictions, caption/message limits, paid sending and the final explicit Send action. As with other native input edits, typing activity follows the current Ghost Mode policy.

Prior-block review: MessageShot settings migration, theme resolution, generation-time snapshot, hidden-heading/date spacing, alpha background setup and standalone SDK-check isolation were inspected. The renderer's width guard was corrected from >112 to >152 so its inner text width is positive. The production width remains 900 pixels. This was a source-level boundary correction; no simulator rendering was performed.

The actual Foundation harness now includes migration/explicit-false settings checks, Repeat text UTF-8/UTF-16 boundaries, whitespace normalization, query punctuation and no-truncation limits. These tests run in the owner's manual Codemagic pre-build step and have not executed on this Windows host. Syntax/import/pinned-patch checks do not establish full native compilation or runtime correctness. No new IPA is produced by this source change; published build 8 does not include these tools.

Device checklist: incoming/outgoing text and captions; formatted/emoji/spoiler text; empty and structured nonempty drafts; current reply; edit mode; recording discard/cancel; read-only/restricted/paid chats; private/group/forum searches and native search cancellation; long/blank text; source access changes; ID clipboard/toast; account switching/restart and all switches off.
